# The review loop — how a diff gets reviewed, iterated, and committed

*Written 2026-09-14 at Michou's direction from his ruling that a blocking review finding opens a fix-and-re-review loop between models before it ever reaches him. ADR-016 fixes the classes and the bound; ADR-019 §7 is the decision record; HANDOFF-0025 adopted this protocol for hand use and HANDOFF-0029 (done 2026-09-17, AUDIT-0016) made it `kgme review`. This reader is the human-readable copy; `kgme.toml` `[models]` is the machine-readable one, and a test checks the two agree.*

## Models
| Role | Provider | Identifier | How invoked | Notes |
|---|---|---|---|---|
| Builder | Claude Code | the session's model | interactive or `claude -p` | Writes the diff |
| Reviewer | Codex CLI | `gpt-6-astra` | `codex exec -s read-only -m gpt-6-astra --json` | Default reviewer; Codex config default model |
| Reviewer, alternate | Codex CLI | `gpt-5.6-sol` | `codex exec -s read-only -m gpt-5.6-sol --json` | Used when Astra reviewed the previous cycle on the same root cause |
| Arbiter | Claude | Opus 5.5 (`claude-opus-5-5`) | Agent tool, model `opus`, read-only | One arbitration per disputed finding; the other lab from the reviewer |
| Also available | Codex CLI | `gpt-5.6-luna`, `gpt-5.6-terra` | same form | Present in the Codex model cache on this machine; unassigned |

A reviewer that must resolve links needs `-s workspace-write -c 'sandbox_workspace_write.network_access=true'` plus a do-not-write instruction and a pre/post SHA-256 check of the tree; read-only is for everything else.

## The commands
| Command | What it does |
|---|---|
| `kgme review --handoff HANDOFF-NNNN` | one cycle on the staged diff: runs `make check` (a red gate is not reviewed), writes the patch and its hash to `logs/scratch/`, appends the `intent`, runs the reviewer, writes the cycle's audit file, appends the `outcome`. Exit 0 PASS, 1 BLOCK or tooling exhausted, 2 usage, 3 halt. |
| `--dispositions FILE` | the builder's answer to the previous cycle's findings, required from the second cycle on; the previous table goes to the reviewer with it, so finding ids stay stable |
| `--reviewer`, `--arbiter` | override the `[models]` defaults; the arbiter is only named in the packet, since it runs through the Agent tool in-session |
| `--patch FILE`, `--skip-check`, `--dry-run` | review a patch file instead of the staged diff; skip the gate; print the prompt and write nothing |
| `kgme review rule --handoff … --finding F2 --class advisory --reason … [--arbiter …]` | record the arbiter's ruling, once per finding; the loop applies it to every later cycle, overrides included |
| `kgme review arbitrate --handoff … --finding F2 [--argument FILE]` | send one finding to the arbiter pair of `kgme.toml [models] arbiters`, in parallel, each a fresh read-only `-p` run on one brief (`control/review/arbiter-prompt.md`); each ruling is its own `ruling:F2@<model>=<class>` note with the brief's path and sha256 in its payload, then one settled `ruling:F2=<class>` (HANDOFF-0043) |
| `kgme loop --queue HANDOFF-A,HANDOFF-B [--workspace PATH] [--stall-minutes 15]` | the unattended mode over a queue: see "The loop" below (HANDOFF-0043) |
| `kgme review --handoff HANDOFF-NNNN:<task> [--workspace PATH]` | a cycle on a KGME workspace's staged diff (HANDOFF-0048): the gate, the diff and the reviewer's working directory are the workspace's, the ledger, the audit and the scratch the main checkout's; the unit `HANDOFF-NNNN:<task>` keys the events, and `:plan` and `:integration` are the crew's own units. `--reviewer claude-…` runs a Claude model read-only through `claude -p` (a Codex-built task's reviewer) |
| `kgme crew --handoff HANDOFF-NNNN`, `kgme crew check-plan FILE` | see "The crew" below (HANDOFF-0048) |
| `kgme workspace create\|list\|quarantine\|release\|remove`, `kgme approve --what code --sha <sha>`, `kgme skills install` | the crew's worktrees, Michou's approval of an integration head, the skills' links (HANDOFF-0048) |
| `kgme review override --handoff … --reason …` | Michou's one-word answer to a halt, as an `approval`; clears the strike window and the halt, keeps rulings and the previous table |

## The cycle
1. **Builder stages the diff** for one handoff and runs `kgme review --handoff <id>`. The command runs `make check`, writes `git diff --staged` to `logs/scratch/review.patch`, and appends a ledger `intent`: `job: review:<handoff id>`, `key: review:<handoff id>:<diff sha256>`.
2. **Reviewer reads** the handoff, the patch, and the acceptance test, and returns findings under the prompt in `control/review/prompt.md`. Every finding carries an ADR-016 class: `blocking`, `transient`, `cosmetic`, `advisory`. A finding without a class is returned to the reviewer once, with the original review, and only the missing classes are merged back; if still unclassed it is recorded as `advisory`. A reply that is not a review (no table, a malformed row, a verdict that contradicts the table, an empty Verdict section) is a failed attempt: up to three attempts with jittered backoff, each a `transient` outcome referencing the intent, then a `blocking` error outcome that closes it and counts as no strike.
3. **Findings land** in `docs/audit/AUDIT-NNNN-review-<handoff>-cycle-N.md`, cells escaped so the table parses back identically, the reviewer's text verbatim below. A ledger `outcome` closes the intent with the diff hash, the class counts, the audit id, and the open blocking ids, inline when they fit or in `state:<outcome id>:<n>` notes when they do not; the reviewer's JSON stream is the outcome's payload.
4. **No `blocking` finding:** the builder commits, binding the commit message to the reviewed diff hash. Cosmetic findings are auto-fixed by `ruff format` if deterministic, else noted. Advisory findings go to the weekly review.
5. **A `blocking` finding:** the builder fixes it and runs the next cycle with `--dispositions`. Each cycle's events carry `parent: <the first review intent id>` so the whole loop is one tree in the ledger.
6. **Disagreement:** if the builder holds that a `blocking` finding is not blocking, the arbiter reads the finding, the diff, and both arguments, and rules once; the ruling is recorded with `kgme review rule` and applied from the next cycle on. There is no second arbitration on the same finding.
7. **A halt** appends the ADR-016 packet to the cycle's audit file and to a payload bound to a `halt:` note, prints it, and refuses every further cycle until `kgme review override` records Michou's answer.

## The bound (ADR-016)
- Strikes count **distinct blocking root causes**, never attempts. The same root cause across three cycles is one strike with an attempt count.
- **Tooling failures never count:** sandbox without network, HTTP 429, `curl` 000, a reviewer timeout. They are `transient`, retried within ADR-016's bound, and if exhausted they reclassify to `blocking: exhausted` against the tooling, not the diff.
- **Halt** (HANDOFF-0043 amendment 16, ADR-023's measured non-convergence, coded in `kgme/review.py` `loop_state` over the window since the last override) when: (a) a settled ruling was executed and the same root cause blocks again in the next cycle; (b) a diff hash is reviewed a second time with no settled ruling between the two reviews; or (c) the last three gates (`gate:` notes, which `kgme review` writes for every `make check` it runs) are red and their failing count never fell. The count of cycles no longer halts; strikes stay as telemetry. Superseded wording, kept for the record: halt when three distinct blocking root causes are still unresolved after the builder's fix cycle and the re-review, or when one root cause has stood blocking in three consecutive cycles. A first-cycle review may raise any number of findings; strikes are what survives a fix. (Wording amended by Michou 2026-09-15 after the first halt fired at the end of cycle one, before any fix attempt; coded in `kgme/review.py` `loop_state` under HANDOFF-0029, which counts the window since the last override.) (ADR-023, accepted 2026-10-16: a count no longer decides by itself. Until HANDOFF-0043 changes `loop_state`, the coded halt still fires at the third cycle and is answered by Michou's override; the ruling of the next rule should settle a root cause before then.)
- **Two cycles, then a ruling (ADR-023).** When a blocking finding is disputed, or one root cause has stood blocking for two consecutive cycles, it goes to the arbiter pair (HANDOFF-0043: `kgme review arbitrate`, which `kgme loop` runs by itself on the two-cycle condition): the two models named by `kgme.toml [models] arbiters`, each in a fresh context that is recorded and then dropped, given the finding, the diff and both arguments, never the builder's conversation; each ruling is recorded as its own event, and agreement settles the finding, while a split takes the reversible option with the smallest blast radius and is listed for the approval screen (a `split:` note). The ruling downgrades the finding, recommends an option (each option with its door, one-way or two-way, and its blast radius), or rules it outside the mandate. The builder executes the ruling in the next cycle; on a split it takes the reversible option with the smallest blast radius and says why. Only an outside-the-mandate ruling, or a ruling executed twice with the same root cause returning, goes to Michou. (Michou's rule of 2026-10-13, that a third patch on the same mechanism is not an option, stands: the ruling replaces the patch. Amended by Michou 2026-10-16.)
- **A fix cycle starts with a red command.** Before the patch, the builder's disposition names, for each `blocking` finding, one command that goes red on that finding's exact symptom (deterministic, seconds, runnable with nobody present) and shows it having run once; where no such command exists the disposition says so, and that absence is itself a finding for the reviewer. A patch without its red command is not a fix cycle. (Michou, 2026-10-14, adopting the Phase 1 discipline of `diagnosing-bugs` in `mattpocock/skills`; the review that brought it in is `memory/agent/2026-10-13-external-repos-review.md`.)
- A halt sends Michou the ADR-016 escalation packet, one screen: what failed, its class, the evidence, the options (override / reject / retry), a recommended default, and what happens if he does nothing (nothing is committed). The intended reply is one word.

## What the loop never does
It never edits an accepted ADR, the charter, or `CLAUDE.md`. It never commits over an unresolved `blocking` finding without Michou's word. It never runs the reviewer with write access to the tree. It never counts a punctuation finding as a strike.

## The loop (HANDOFF-0043)

`kgme loop --queue HANDOFF-A,HANDOFF-B` runs adopted handoffs (at the top of `docs/handoff/`, `status: open`, from `cowork` or `michou`), in the order named, each to its close, with nobody watching. It adds no prompt and does not drive the build step by step; it starts a fresh `kgme session loose --handoff <id>` per handoff, as its own process group, in the workspace it is given, and reads the run back from the ledger, never from the builder's report.

- **Close.** The builder's session ends with a PASS review as the newest cycle since the run started: the closing `outcome` names the commit, the audit ids and the usage the builder's stream reports. A session that ends without one is an `error` outcome, and the queue goes on.
- **Halts** are the three measures above. The loop kills the run's group, the packet stands in the ledger, nothing is committed, and the queue goes on to the next handoff; the halted handoff waits for Michou's override.
- **Arbiters.** A finding blocking two consecutive cycles with no settled ruling goes to the pair, once per finding; the builder executes the settled ruling in its next cycle.
- **The stall switch.** A run whose newest ledger event is older than `--stall-minutes` (default 15), with no call of the session alive, on two consecutive polls, is killed (SIGTERM to the group, SIGKILL ten seconds later), written as a `blocking` outcome "stalled run killed", and its scratch moves to `logs/scratch/loop/quarantine/<run>/`. A long single call (`make check`, a review) is not a stall while its process lives.
- **The pause.** A limit message in the builder's output pauses the queue until the reset it names, or retries every 30 minutes when it names none, then starts the same handoff again. A pause is a `transient` note; it is never a cycle or a strike.
- **Compaction.** A compaction in the builder's stream is a `transient` note with the context size the stream gives; it is not a cycle. A compacted builder finds the cycle's diff, dispositions and findings on disk: `logs/scratch/review.patch`, `logs/scratch/review.dispositions`, and the audit file the ledger's last cycle names.
- **Sleep.** `caffeinate -i -w <the loop's pid>` holds the Mac awake exactly as long as the loop lives.
- **Never.** The loop never edits a handoff's work or its acceptance test, never runs the reviewer or an arbiter with write access, never merges, never commits over a halt, never pushes (the post-commit hook does, to `origin` only), never runs a login, and adopts no proposal: a defect it finds outside the queue becomes a proposal under `docs/handoff/proposed/` with its diffs under `logs/scratch/`, for Michou.

## The crew (HANDOFF-0048)

`kgme crew --handoff HANDOFF-NNNN` plans, builds and integrates one adopted handoff with nobody watching, and stops at `awaiting approval`.

- **The route (amendment 2).** A `loose` builder in a KGME workspace (`kgme.toml [crew] root`, `~/Projects/KGME/work/<handoff>-<task>/`, a worktree on `crew/<handoff>/<task>` from the integration head) runs `uv run --frozen --project <main checkout> kgme review --handoff <handoff>:<task>` (on its pinned list and excluded from the sandbox, so the reviewer reaches its provider and the ledger and audit are the main checkout's) and commits on its own branch by `git add -- <paths>` and `git commit -- <paths>`, the two git writes on its list; a push, a checkout and every other git write stay off it, and the merge gate refuses a branch that carries anything outside the task's Outputs. `tests/test_loose_route.py` is the named case; nothing runs under `kgme loop` outside its tests until it is green.
- **Workspaces.** `kgme workspace create --handoff … --task … --outputs …` makes the worktree and its record (`logs/scratch/workspaces/<name>/task.json`, in the main checkout, never in the worktree); `quarantine` kills the task's group, renames its branch `quarantine/<run>/<task>`, moves the worktree under `<root>/quarantine/`, removes write permission and writes a `blocking` outcome; `release` and `remove` are Michou's and refuse under an agent harness. The integration branch is `crew/<handoff>/integration`: git refuses `crew/<handoff>` beside `crew/<handoff>/<task>`.
- **The plan.** The planner is a fresh read-only `claude -p` on the `kgme-planner` skill; its reply is the plan (`logs/scratch/crew/<run>/plan.md`). The plan gate (`kgme crew check-plan`) refuses a task without Outputs or an acceptance check, overlapping Outputs with no edge, a cycle, a human or blocklisted path, or a width over `[crew] max_width` (the plan gate's cap; `[crew] parallel` is the dispatch width); a red plan goes back to the planner and is not reviewed. A green plan is one `kgme review` cycle on the unit `<handoff>:plan` with `control/review/plan-prompt.md`, by a reviewer of the other vendor, with the same arbitration and halts as a diff; the loop stops on a plan seen before, a halt measure, or `[crew] max_plan_cycles`, and dispatches nothing.
- **Dispatch.** `[crew] parallel` ready tasks (1) in plan order, each in its workspace, each through `kgme loop` on its unit with its adapter: Claude Code through `kgme session loose --handoff … --task …`; Codex through `codex exec --json -s workspace-write` with the worktree as its only writable root, its commands ledgered from its stream, its review and commit run by the supervisor (its sandbox has no network), its reviewer a Claude model. A halted or stalled task is quarantined; its dependents wait; independent tasks go on.
- **The merge gate.** Before a task branch merges: changed paths a subset of its Outputs; no human path, blocklisted path, symlink or binary; no secret (`[crew] scanner`, else the built-in rules); no zero-width or bidirectional control character; a dependency change refused (its toolbox row is a human path); `make check` and the task's acceptance check green on the merge result in a trial clone. A refusal quarantines the task; green, `crew/<handoff>/integration` is moved to the trial's merge commit.
- **Integration and approval.** The full gate on the integration head, one review on the unit `<handoff>:integration` by a vendor other than the majority of builders, then an `awaiting approval` outcome naming the commit and one screen. `kgme approve --what code --sha <sha>`, typed by Michou, appends the approval and fast-forwards `main` from that head only when it is a `crew/<handoff>/integration` head the crew named; the crew pushes nothing, the post-commit hook pushes `main`.
- **Skills.** `kgme skills install` (Michou's) links each `skills/<name>/` into `~/.claude/skills/`, `~/.agents/skills/`, `.claude/skills/` and `.agents/skills/`, refuses to overwrite a skill it did not install, never touches `~/.claude/skills/synced/`, and `kgme lint` checks a copy's hash where a link is not followed.
