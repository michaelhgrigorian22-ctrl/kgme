## What was built
1. **`mods/kgme-cockpit/`, the pane** (§2).
   - **Lifecycle:** `session.start` opens it, and `ui.render` draws it from `$.state`.
   - **Polling:** `$.clock.every(2000)` polls `http://127.0.0.1:8642/api/events` (loopback only), with `?since=<cursor>` after the first poll.
   - **Contents:** the server's open runs and their states, the last events, an amber line counting the open runs the server calls `waiting` (an intent with no outcome yet), and a magenta line for a blocked run. The open runs are exactly the ones the poll calls open, because the server returns every still-open run with each poll.
   - **Failure:** when the fetch fails it says "server not reached" and keeps the last snapshot.
   - **Boundary:** it decides no state and binds no key. A status-line entry names the newest run's state.
2. **`mods/kgme-capture/`, `/capture <kind> <words>`** (§3). `session.start` registers the command, and `command.run` runs the one `$.process` call, `kgme capture <kind> <words>`, from the session's folder. It returns what that printed, verbatim. One pair of quotes around all the words is dropped, as a shell would.
3. **The launcher** (§4, `kgme/session.py`, `kgme/session_logic.py`).
   - `kgme session` passes `--plugin-dir <repo>/mods/<name>` for each mod `kgme.toml [mods]` names for the level, and records them in the session's note.
   - `loose` and the cheap lane load none, whatever the table says: `build_argv` refuses a `loose` launch with a plugin folder.
   - A named mod that is not a mod folder, or is a symlink, stops the launch.
4. **The check** (§1's last line, `kgme/mods.py`, a step in `make check`). For every folder under `mods/`, `claude plugin validate --json` is run, and its listing (the hooked events, and the `$` calls by noun) is held to `kgme.toml [mods.allows]`. Each of these is blocking:
   - a hook or call more than the allows list names;
   - a folder with no entry;
   - a failed validation;
   - a non-mod folder;
   - a mod folder on a machine without `claude`.

   With no mod folder the step passes.

## Design decisions, each recorded
- **The allowance lives in `kgme.toml [mods.allows]`,** not in the handoff's prose. ADR-024 says a listing that names something "its handoff did not" is blocking. Reading that out of a handoff fails on 0059 itself: its text names `tool.call` in "Not in this handoff: any `tool.call` hook", so a planted `tool.call` would pass. `kgme.toml` is a human path adopted with the handoff, so no agent can widen it.
- **`/capture` runs `uv run --frozen kgme capture <kind> <words>`,** not `["kgme", "capture", …]` as §3 writes it. `kgme` is a shell function (`uv run --frozen --project "$KGME_HOME" kgme`), and `$.process.run` runs without a shell, so a bare `kgme` would not start. Its project is the checkout `kgme session` launched from: the launcher sets `UV_PROJECT` to it for every level that loads a mod, and `uv` reads that natively (review cycle 1 F2). It is still the one call: KGME's own command, with his words and nothing else.
- **The test fixture carries no mods.** `tests/sessiontools.py` built every fixture's settings from the repository's own `kgme.toml`. With the `[mods]` diff applied, 14 session tests failed in the acceptance clone, because each fixture checkout named mod folders it does not hold. The fixture now sets `mods: {}`, and a test that loads a mod sets its own.
- **`run_check`'s `claude` argument:** `None` looks it up on PATH, and `""` means none is installed. My first version treated `""` as "look it up", and a test caught it.
- **The validator's directory findings are not enforced.** `claude plugin validate` also lists the plugin directory's submission findings (no LICENSE, no icon). They are the marketplace's, not a local mod's, and the check reads `success`, the errors and the listing only.
