## What was built
1. **`kgme capture <remind|task|friction|note|daily> "<words>" [--due <when>]`.** A reminder, task, or note is a new file under `memory/notes/`. It is rendered from its template, keeping the template's keys in order and its defaults (`repeat: null`, `channel: phone`, `priority: 2`), with a ULID `id` (schema v1.5: an agent writes a ULID), `created` and `modified` now, `source: stated`, `author: kgme`, and his words as the `#` title. The filename comes from the first eight words in kebab-case; a taken name gets `-2` and on. The file is published by `capture_fs.write_new`: a temp file created `O_EXCL` inside a checked directory descriptor, written whole and fsynced, then hard-linked to the name, which fails on an existing name and never replaces, so the destination is absent or complete, never partial. A friction entry is one line added at the end of `memory/inbox/friction-log.md` in the log's stated format, `- YYYY-MM-DD HH:MM — <words>`. A daily line is `- <words>` under the closing `## Michou` heading, and the heading is added first when the note does not end under it. Either is written by `capture_fs.write_replaced`, a whole-file atomic replace under the vault lock (the arbiter's ruling after AUDIT-0062; review cycles 5 and 6): the file is read on a descriptor opened inside a checked directory descriptor (no link above, none in place, a regular file); its bytes plus the line are written, `O_EXCL`, with its mode, and fsynced to `.<name>.capture-<intent id>` beside it; the two names are exchanged in one step (`renameatx_np` with `RENAME_SWAP` on macOS, `renameat2` with `RENAME_EXCHANGE` on Linux), and the displaced file is read. If it is not exactly what was read, an editor outside the lock saved meanwhile: the exchange is undone and the capture refused, the save in place. The file holds its old bytes or its new ones, so a torn line cannot exist. **Capture deletes nothing, ever** (cycle 6 F13 and F15, ruled by two arbiters, with Cowork's refinement): after the exchange the kept name holds the displaced copy, a gitignored dotfile Obsidian does not show. Before the copy exists, a `kept` ledger note records the sha256 prefixes (32 hex digits, under the redactor's 40-character rule) of the file as read and as intended; payloads are disposable, the ledger is not. `kgme clean kept` removes a copy only while it hashes to one of them, and refuses and names any other. A copy that differs holds a save the file lacks, so every later capture into that file refuses, naming it, until Michou merges it by hand. Every capture is one `intent` and one `outcome`. The intent's payload, bound by sha256 and read back only through `ledger.read_payload`, holds the destination, the mode, the offset and size, the exact bytes added, for a replace the sha256 of the whole file as read and as intended, and the words: what reconciliation checks, and what the output is reconstructed from. The command prints the file or line it wrote. A capture carries an idempotency key (kind, words, due words, day): when an `ok` outcome already answered that key, a retry or a duplicate run writes nothing and prints "already captured". `--dry-run` prints the destination and the bytes, writes nothing, and appends one `note`. A refusal is one intent and one `refused` outcome of class `blocking` that keeps his words, so nothing he said is lost.
2. **`--due` is read, not guessed.** A stdlib reader in the `[brief] timezone` zone, written ISO 8601 with its offset (`nov 3` gets `-08:00`). It understands today, tomorrow, weekdays (the next one; today only while its time is ahead), ISO dates, `oct 20` or `20 october`, `in N days` or `in N weeks`, each with an optional `9am`, `9:30 pm`, `14:00`, `noon`; 09:00 when no time is given, as in the template. A time alone means its next occurrence. Refused, with what was not read: unreadable words, `next friday` and `this friday` (ambiguous), impossible days, passed instants, and a reminder with no due.
3. **`kgme daily [--date D]`.** It creates `memory/daily/<date>.md` only when the note does not exist and the ledger holds an event of that day. A second run, a note Michou began himself, or an empty day writes nothing and records nothing; `--dry-run` prints the draft and appends one `note`. The note is published as a capture's is, under a payload-bound intent. The five template sections are each marked `inferred` and say what they were drafted from; each line ends with the event id, commit, handoff, or report it came from, and all of those are in `sources`. A closing `Michou` section is marked `stated`. Sources: the day's ledger (job outcomes, Michou's `ledger note`s, rulings, blocked and refused outcomes, each paired only with what explicitly answers it (a later `ok` under the same key, a later PASS of the same review, Michou's override), else "still open", the tool-call count), one bounded read-only `git log` of the day (subjects, and the handoff files each commit renamed), the handoffs and the day's reports under `docs/`, the open reminders and tasks (read and validated through the brief's own readers), and the friction log.
4. **One run at a time over the vault.** `kgme-vault.lock` in the git directory is shared by both jobs, so an open intent with no holder belongs to a run that ended. Every intent whose result the ledger does not settle (open, or closed `error` after its announce) is read against its file by one classifier that compares the file's bytes with what the intent recorded: `done` (a new note holds exactly its bytes; a replaced file hashes to its intended bytes and its kept copy, if any, to the bytes it was read as), `absent` (no new note; a replaced file still hashes to the bytes it was read as and its kept copy, if any, to the capture's own), `conflict` (anything else), `unknown` (no bound payload). On start an open intent is closed `ok` when done and `transient` when absent; a conflict or unknown state stops the run and names the file. A failure after the announce is classified before its intent is closed. A retry skips an `ok` attempt without reading bytes, because Michou edits these files, and classifies any other. A held line is done from its verbatim summary when its payload is gone. `kgme daily` settles both jobs' intents before it reads the held lines.
6. **The morning brief reads the evening's draft.** Until the day's own note exists, `kgme brief` reads the previous day's, so a note drafted at 21:30 is in the next morning's brief, as the handoff's item 4 requires.
5. **Agents capture on his word.** One line in `CLAUDE.md`, last under "How decisions are made".

## Decisions made on the route (ADR-023 scores, stakes × edge)
- **A `capture daily` before the day's note exists is held verbatim in the intent's summary, and `kgme daily` writes it into the draft.** Creating the note at capture time would stop the 21:30 draft from ever being written, since `kgme daily` creates the note only when it does not exist. Scratch payloads are deletable by `kgme clean scratch`, so the ledger summary is the durable place. The cost: words over about 170 characters, or words the redactor would alter, are refused before the draft with a message to run `kgme daily` first. 3 × 0.3 = 0.9, **listed for the approval screen.**
- **`author: kgme` under `memory/notes/`**, as the handoff says. The validator reports every captured note as `advisory` ("a kgme note under a human folder"). The alternative was `author: human` on a file a machine wrote. 2 × 0.3 = 0.6, **listed for the approval screen.**
- **The idempotency key is the kind, the words, the due words, and the day** (cycle 1 F3). The same friction said twice on the same day is captured once, and the second run says "already captured"; on another day it is a new entry. 2 × 0.3 = 0.6, **listed for the approval screen.**
- **The brief reads the previous day's note until the day's own exists** (cycle 1 F6). This changes `kgme brief`, which belongs to HANDOFF-0034, so that item 4 of this handoff holds. 2 × 0.2 = 0.4.
- **`next friday` refused as ambiguous**, rather than read as the coming Friday or the one after. 2 × 0.3 = 0.6, **listed for the approval screen.**
- **The brief lists a reminder only on or after its due day** (see the acceptance test above). Brief v1 is outside this handoff; an "upcoming" section is a one-function follow-up. 2 × 0.4 = 0.8, **listed for the approval screen.**
- `kgme daily` reads `git log`, because the ledger holds neither commit subjects nor handoff moves: tool-call summaries carry a fragment count, not the command. Declared as tool `git` in the daily manifest, read-only, bounded by `[sync] git_timeout_seconds`; when git cannot answer, the draft says so in one line. 2 × 0.2 = 0.4.
- Commits by `kgme sync` (subject `ledger: `) become one count; a commit that moved more than three handoff files becomes a count per destination folder. HANDOFF-0049's single commit would otherwise be 35 lines of a daily note. 1 × 0.2 = 0.2.
- Friction lines use the log's stated format with the time, `- YYYY-MM-DD HH:MM — <words>`. Recent entries Cowork wrote omit the time and quote the words; the stated format line wins, and his words go in unquoted because they are verbatim. 1 × 0.3 = 0.3.
- The daily `Friction` section takes every friction-log line dated that day, not only those `kgme capture` wrote, so Cowork's appends in the identical format count too. 1 × 0.1 = 0.1.
- An unreadable `--due` is a recorded refusal (exit 1), not a usage error, so the words reach the ledger. Empty words, a line break, or `--due` on a kind without one exit 2 and record nothing. 1 × 0.2 = 0.2.
- Summaries are redacted before they are clipped; reconciliation and reconstruction never read a summary (cycle 1 F4). A defect found by the tests: a clipped summary could grow past the 200-character cap under the ledger's own redaction, and the ledger write would then raise. 1 × 0.0 = 0.
- The reader was blocked by the deny rule. Michou was asked, and approved the copy; the settings refused it. The reader is left to him rather than written by another route. 3 × 0.6 = 1.8, **asked.** He took the recommendation (apply), and the settings overruled the route.
- **A capture refuses when an editor saved during it, keeping the save** (cycles 5 and 6); he says the words again. The ruling said "rename over the original"; an exchange of names is that rename made checkable, macOS and Linux only (elsewhere the capture is refused). A save written through a descriptor held across the exchange now lands in the kept copy, and the next capture into that file refuses and names it, so nothing he wrote is lost, though it waits in a hidden file until he merges it. A retry of the same words after a refusal reads `conflict` and refuses until checked by hand. 3 × 0.2 = 0.6, **listed for the approval screen.**
- **Kept copies accumulate** beside the friction log and the daily notes, one per line added, each the size of its file, until `kgme clean kept --yes` runs; nothing schedules it in Phase 1. 2 × 0.3 = 0.6, **listed for the approval screen.**
- **Two manifests widen, on Cowork's note.** `jobs/capture/manifest.toml` may read and write `memory/inbox/.friction-log.md.capture-*` (the daily copies are under `memory/daily` already), and `jobs/clean/manifest.toml` may read and delete `memory/**/.*.capture-*`: the first time `kgme clean` may delete anything under `memory/` outside `memory/agent`, gated on the recorded hash. Manifests are permissions, Michou's boundary, so this is on his approval screen. 3 × 0.3 = 0.9, **listed for the approval screen.**
- `capture_fs.write_new` still removes its temp name, after the new note is linked to it (the inode stays as the note) or on a failure before that, when it holds only the capture's own bytes. No byte anyone else wrote is removed. 1 × 0.2 = 0.2.
