## What was built
1. **`kgme atlas`** writes `atlas/` at the repository's top: one note per node, 307 on this tree, one per node, in `atlas/<kind>/<name>.md`, each opening with one line saying what the node is, linking its file, and listing its neighbours as `[[...]]`, sorted.
   - **Folders:** each top-level folder of the tracked tree, whatever it holds (`memory/`, `logs/`, and `cockpit/` included), linked to every node it contains (review cycle 1 F4).
   - **Files an `Outputs` names:** every tracked file a handoff's `Outputs` names that is not otherwise a node becomes a `file` node (`jobs/brief/job.md`, `memory/templates/daily.md`) and is linked from it (F5).
   - **Code:** each module in `kgme/`, `jobs/`, and `control/` (Python and shell), linked to the modules it imports, read with `ast` and never executed (a shell script by the `kgme.*` modules it runs), to the tests that import it, and to the ADRs its text cites.
   - **Tests:** each test module.
   - **Documents:**
     - each ADR, linked to the ADRs it supersedes or cites and to the handoffs that cite it;
     - each handoff, linked to `depends_on`, `plan_ref` (its plan row), the files of its `Outputs` (globs and braces expanded), its `report`, and the ADRs it cites;
     - each row of the phase plan, linked to the handoffs it names;
     - each reader, linked to the folders and modules it names;
     - each audit, linked to its handoff and the ADRs it cites.
   - **Kinds:** frontmatter `kind:` (folder, module, test, job, file, handoff, adr, plan, reader, audit, skill, project) for the colour groups, and `generated: kgme atlas`, the mark that lets a later run remove only notes the atlas wrote.
   - **Links to the real file:** a Markdown document as `[[docs/...]]`, code as a plain relative link.
2. **The vault is the repository.**
   - **Moved:** the seven tracked settings files moved from `memory/.obsidian/` to `.obsidian/` with `git mv`. Their folders gained `memory/`: new notes in `memory/notes`, attachments in `memory/attachments`, daily notes in `memory/daily`, templates in `memory/templates`.
   - **Excluded:** `.venv/`, `logs/`, `kgme/`, `jobs/`, `control/`, `tests/`, `cockpit/`, and the caches.
   - **Graph view:** `graph.json` holds the saved view, filtered to `path:atlas` with one colour per `kind`, `file` included (review cycle 2 F8).
   - **Ignored:** `.obsidian/workspace.json` and its cache, as `memory/.obsidian/`'s were. The old untracked `memory/.obsidian/workspace.json` is left for Michou to delete.
3. **Regenerated without anyone asking.** The post-commit hook runs `kgme atlas` in the background after every commit on any branch: on `main` after `kgme sync`'s push, in the same subshell; on another branch alone, since it pushes nothing (review cycle 1 F3). A checkout whose code predates the atlas (no `kgme/atlas.py`, as the design worktree's today) skips it. `kgme sync`'s own ledger commits exit before it, so a ledger commit does not regenerate it. `kgme atlas` writes nothing to the ledger on success. A failure (no checkout, a refused path) is one ledger `note` of class `transient`, `job: atlas`, and exit 1, which the hook ignores, so a commit never fails on it. It takes 0.29 s on this tree. `atlas/` is ignored by git.
4. **Across projects, later and opt-in.** `kgme.toml [atlas] projects` (empty) lists folders by path, a relative one resolved against the checkout, never the working directory (F6). Each is read by structure only: its top-level folder names (no link followed), its `README.md`'s link targets, read as a regular file through no link (F2), and the KGME parts that README names (`kgme <job>`, `kgme/<module>.py`). No other file's contents are read. A project at, inside, or containing a Tier 1 root is refused (ADR-002). Each is one `project` node linked to the KGME parts it uses.
