# The station (CDH-0009, cycle 2 under CDH-0012)

A second wall layout: the ship, its rooms and the crew at work, drawn dark and on theme. Not a canvas artboard (a rendered scene is script-built, which the `.dc.html` editor forbids): one hand-built page.

- `index.html` — the page. Serve `docs/design/cockpit-v0/` over HTTP (`python3 -m http.server 8080` from that folder) and open `/station/`. It reads the cast from `../chibi/*.svg` at load and replays `sample-events.jsonl` at ×20, looping. Two read-only query parameters exist for checks: `?speed=N` (replay rate, 1–60, default 20) and `?at=HH:MM:SS` (start the replay at that clock on 2026-10-08).
- `sample-events.jsonl` — 40 ledger lines in ADR-019 event v1 shape, one JSON object per line, derived from the samples boards 3, 5 and 11 carry (2026-10-08, 19:40 to 19:52). Ids are ULID-shaped; raw bodies never appear. The sample holds no halt note and no approval; the halt path is shown with a two-line synthetic sample kept under `logs/scratch/design-review/cdh-0012/` for the review, never here.
- The page loads the pinned `three@0.182.0` package from jsDelivr through an import map (`three.module.min.js` and `examples/jsm/`) and the repository's own files, nothing else: no font is fetched (the type is the system monospace, AUDIT-CDH-0011 S6). The cockpit itself may load nothing remote (ADR-017); HANDOFF-0044 proposes vendoring the module as plain text under `cockpit/static/vendor/` when the station leaves the design track.
- Rooms are KGME places: Bridge (you), Workshop (`claude-code.*`), Review chamber (`kgme.review`, `arbiter.*`), Airlock (`kgme.guard`), Archive (`kgme.*`), Dock (shells, the stranger), Engine room (phase 2, dashed). The sprite mapping is a copy of `kgme.toml [sprites]`, first match wins.
- Words first, from one snapshot (AUDIT-CDH-0011 S1): every 250 ms the page builds one textual snapshot — clock, ledger line, session, harnesses, the hull (`nominal`, or `HALT · <the note>` while a halt note is a run's newest event), the tray summary, each room's state line, each run's row, and the last event of the bridge (Michou's note or approval), the airlock (the guard's last refusal) and the review chamber (the arbiter's last ruling), which stay as text after their bubbles fade. The HUD, the room chips, the pane and the wall all read that snapshot; the lights mirror it and never replace it. Keys: `1`–`7` follow a room, `Esc` the whole deck, `a` the runs pane, `c` calm (drops to the wall: the HUD stays, the deck, frame, portraits and micro labels go, every fact remains), `r` restarts the replay. Reduced motion removes bloom, walks and fades, and is observed while the page runs.
- Rows are keyed by run and updated in place (S4): a focused row survives every refresh. The room buttons stay in the accessibility tree with their state in their name; the canvas and the crew artwork are the only parts marked decorative (S3). Every muted line of a focused row is `#7a8d9b` (S5).
- Lifecycle words, as on board 11 (S2, S7): working · waiting (the newest intent or outcome is an intent, with no outcome yet, whatever its parent) · transient (the newest outcome is class transient, or an exhausted retry that names a time) · blocked (the newest outcome is class blocking, or a blocking note that no intent, outcome or approval has followed) · quiet (a working run with no event for longer than its median gap between intents, and never less than three minutes; with fewer than two intents, three minutes). A job run closes with the outcome of its run intent; a hook session stays open until a `session:end` note.
