# Handoff 0028 (proposed) — The hook pair: pre-tool guard, post-tool ledger

## Why
The original step 1 asked for a post-tool hook that appends to a ledger that did not exist. With 0026 done, the hooks become the ledger's first client and the first live instance of ADR-013 §4: the pre-hook writes the `intent`, the post-hook writes the `outcome` with `ref`. Michou ruled 2026-09-14 that every tool call is recorded, including Read, Grep, and Glob, and that only a redacted summary reaches the ledger while the raw input goes to gitignored scratch. Under ADR-019 §2 the writer routes read-only tool pairs to the untracked trace stream and everything else to the git-tracked ledger; the hook does not choose. The pre-hook is also the enforcement layer ADR-008 named: it blocks by resolved path, which string patterns in settings cannot do for symlinks and nested `.env` files.

## What
1. `tools/hooks/pre_tool_guard.sh` (three lines): grep pre-filter on stdin for guarded patterns and any file path; if nothing matches, exit 0 without starting Python; otherwise `exec uv run --frozen --project "$CLAUDE_PROJECT_DIR" python "$CLAUDE_PROJECT_DIR/kgme/hooks/pre_tool_guard.py" || exit 2`. A crashed guard fails closed.
2. `kgme/hooks/pre_tool_guard.py`: read hook JSON from stdin (`session_id`, `tool_name`, `tool_input`, `tool_use_id`, `cwd`); extract paths (`file_path` for file tools; `shlex.split` of `command` for Bash, every token `expanduser().resolve()`); deny with exit 2 and a one-line reason on stderr if any resolved path is under the `[hooks]` blocklist in `kgme.toml` (`~/.ssh`, `.env*`, Tier 1 paths, `~/Library/Keychains`, `~/.claude/` and `~/.codex/` credential stores, `memory/private/`); on allow, `append` an `intent` with `job: tool:<Name>`, `run_id: session_id`, `key: tool_use_id`, `parent: <the session's first event id, else null>`, summary = tool name plus resolved paths (the writer routes it to trace or ledger by the tool name); on deny, append an `outcome` with `class: blocking, status: refused`. Any internal exception is caught, logged as a `blocking` outcome, and exits 2 (ADR-015's no-swallow rule is satisfied by the ledger event).
3. `tools/hooks/post_tool_ledger.sh` and `kgme/hooks/post_tool_ledger.py`: write the raw `tool_input` and `tool_response` to `logs/scratch/payloads/<id>.json`; append an `outcome` with `ref` to the intent found by `key: tool_use_id`, `status: ok|error`, `payload_ref`, `payload_sha256`, redacted summary. If the ledger write fails, write the failure to `logs/scratch/hook-errors.jsonl` and exit 0 (the tool already ran; `make check` surfaces the file and fails if it is non-empty).
4. `.claude/settings.json`: `PreToolUse` and `PostToolUse` entries, matcher `.*`, timeouts 5 s and 10 s.
5. `tests/test_hooks.py`: six synthetic payloads to the guard.

## Outputs
`tools/hooks/pre_tool_guard.sh`, `tools/hooks/post_tool_ledger.sh`, `kgme/hooks/__init__.py`, `kgme/hooks/pre_tool_guard.py`, `kgme/hooks/post_tool_ledger.py`, `tests/test_hooks.py`, two entries in `.claude/settings.json`.

## Acceptance test (under five minutes)
Six stdin payloads give exit codes 2, 2, 2, 2, 0, 2 for: a `.env` read, `~/.ssh/id_ed25519`, the Tier 1 path, a path outside the repo, a benign read of `kgme/paths.py`, a malformed payload. One live session: a real refused read shows an intent and a `blocking` outcome; a real allowed read shows an intent and an `ok` outcome whose `ref` matches, both in `logs/trace/`; a real `Edit` shows the same pair in `logs/ledger/`; the payload file exists in scratch and its hash matches the line; `git status` shows only `logs/ledger/2026-09.jsonl` changed and nothing under `logs/trace/`; a deliberately introduced syntax error in the guard makes every tool call fail closed.
