# Handoff 0051 (proposed) — The atlas: Obsidian as a lens on how KGME's parts connect, regenerated on every commit, never edited by hand

## Why
Michou, 2026-10-16: "i mainly wanted obsidian for the clear view into all the connections between my directories and my codespace ... it should be a low intervention tool that only serves as a lens. Literally just taking advantage of this specific part of its UI, and nothing more", and, since KGME "is the tool I am building that will help me then accelerate my projects elsewhere", "Obsidian should connect the dependencies built across projects at some point."

Why the graph stayed empty: Obsidian draws only the links written inside Markdown notes in its vault. The vault was `memory/` (ten notes, almost no links), and KGME's documents name each other in backticks (`HANDOFF-0034`, `kgme/ledger.py`), which Obsidian does not read as links; code imports it cannot see at all. Obsidian does watch its folder and redraw the moment files change, so once the links exist as notes the lens keeps itself current.

## What
1. **`kgme atlas`** writes `atlas/` at the repository's top: one short generated note per node, each linking its neighbours with `[[...]]`, and nothing else in the tree changes.
   - Folders: each top-level folder, linked to what it contains.
   - Code: each module in `kgme/`, `jobs/` and `control/`, linked to the modules it imports (read with `ast`, never executed) and to the tests that import it.
   - Documents: each ADR (links: `supersedes`, the ADRs it amends, the handoffs that cite it), each handoff (`depends_on`, `plan_ref`, the files and modules of its `Outputs`, its `report`, the ADRs it cites), each plan row, each reader (the folders and tools it explains), each audit (its handoff).
   - Each node opens with one line saying what it is and links the real file: Markdown documents as `[[docs/...]]` (they live inside the vault), code as a plain relative link that opens in the editor.
   - Frontmatter `kind:` (folder, module, test, job, handoff, adr, plan, reader, audit, skill) for the graph's colour groups.
2. **The vault becomes the repository.** `.obsidian/` moves from `memory/` to the top of the repository (tracked, `workspace.json` ignored as now). Obsidian's excluded files: `.venv`, `logs/`, `kgme/`, `jobs/`, `control/`, `tests/`, `cockpit/`, caches. A saved graph view filtered to `path:atlas` with one colour per `kind`. Michou opens `~/Projects/KGME/brain` as the vault once; after that it is a window he glances at.
3. **Regenerated without anyone asking.** The post-commit hook runs `kgme atlas` in the background after the push (under one second on this tree; a failure is a `transient` ledger note, never a failed commit). `atlas/` is ignored by git: it is a view, regenerable from the tree at any commit.
4. **Across projects, later and opt-in.** `kgme.toml [atlas] projects` lists other folders by path, empty until Michou adds one. For a listed project the atlas reads structure only: folder names, its README's links, and which KGME skills, jobs or tools it uses; never file contents. A project holding Tier 1 data is refused (ADR-002). Each project is one node linked to the KGME parts it depends on.

## Outputs
`kgme/atlas.py` (effects: `write_atlas`; logic: `read_imports`, `read_doc_links`, `build_graph`, pure), `kgme/cli.py` (`atlas`), `control/git-hooks/post-commit` (one backgrounded line), `.gitignore` (`atlas/`), `.obsidian/` (moved, with the graph view and exclusions), `tests/test_atlas.py`, a section in `docs/readers/obsidian.md` (as a diff Michou approves; Part 2's daily-note setup is superseded by HANDOFF-0050).

## Acceptance test (under ten minutes)
After a commit, `atlas/` exists within seconds; opening the repository as a vault and the saved graph view shows HANDOFF-0034 linked to `kgme/brief*.py`, ADR-019 and its report, `kgme/ledger.py` linked from the modules that import it, ADR-023 linked to ADR-016; `git status` shows nothing new; a second `kgme atlas` on the same tree writes identical files.
