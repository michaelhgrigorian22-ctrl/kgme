# Handoff 0044 (proposed) — The toolbox: third-party code and APIs as a cheap, visible act, and a scout that finds them

## Why
Michou, 2026-10-13 13:17: "using multiple packages and repos work to build even more intricate and interesting projects is also something we should do way more often. github is filled with insane tools and massive api lists and shit that would take KGME to the next level if we started working them in."

The constitution does not forbid this; it prices it. ADR-015: "Standard library first. A third-party dependency costs an ADR line: what, why, source, pinned version." ADR-008: "Adding a dependency is a visible act." ADR-017: the cockpit is plain text, every dependency in the same `uv.lock`, no generated bundles, no remote asset at runtime. Those rules were written so a human who is not a professional programmer can still audit the tree a year on. They were not written to keep good tools out; they were written so that a tool, once in, can be named, pinned and removed. Today the price is paid by hand and nobody is looking for tools, so the answer to "should we use X" is usually "we never asked." This handoff makes the price one row in one file and adds the looking.

## What
1. **ADR-020 — the toolbox** (draft for Michou's acceptance; the diff shown under ADR-004). One rule in four lines: a third-party package, model, dataset, asset pack or API enters KGME through one row in `docs/toolbox.md`: name · what it is for · where from (URL) · license · pinned version and sha256 of what we hold · egress host it needs, if any · where it is used · the handoff that brought it in. Python packages stay in `uv.lock` (the row points at it). JavaScript libraries the cockpit serves are vendored as plain text under `cockpit/static/vendor/<name>-<version>.js` with the sha in the row, since the cockpit may load no remote asset and has no build step; a minified file is a bundle and does not qualify, the unminified module does. Binary assets (character packs, fonts, models) are never committed: a `make assets` target fetches them by pinned URL and sha into a gitignored folder, and the row records both. An API is a row too, with its secret in the vault (ADR-008) and its host in the egress allowlist (HANDOFF-0038); the router (ADR-007) is the only caller. A row without a sha, a license or a host is a `blocking` lint finding. Removing a tool is deleting its row and what the row points at.
2. **`docs/toolbox.md`** seeded with what is already in the tree: `uv`-locked packages, `ruff`, `pytest`, Playwright (CDH-0001's fixture harness), three.js r182 (reserved for CDH-0009's station, vendored when the station leaves the design canvas), Codex CLI and Claude Code (as harnesses, not dependencies, listed for the egress hosts they need).
3. **`kgme lint`** checks the toolbox: every `import` outside the standard library in `kgme/` and `cockpit/`, every `<script src>` in `cockpit/`, and every file under `cockpit/static/vendor/` has a row; every row's sha matches the file it names. Advisory for a row missing a license at first; blocking from the next schema line.
4. **The scout — `jobs/scout/job.md`**, weekly, Codex read-only with network to `api.github.com` and the package registries only (the egress allowlist gains those two hosts for this profile and no other): reads the roadmap's open items and the proposed handoffs, searches GitHub for tools that would shorten one of them, and writes `docs/audit/scout-YYYY-MM-DD.md`: at most ten candidates, each with stars, license, last commit, what it would replace or add, the egress it needs, the obvious risk, and a one-line verdict. No install, no clone, no code run. Michou reads it on Sunday; a candidate he wants becomes a handoff whose first line is its toolbox row. The scout's first run is pointed at three things already named: an agent-activity visualiser to compare against CDH-0009 (`agent-world-viewer`, `claude-office`, `pixel-agents`), a Kalshi/Polymarket-style event feed as a test of the API path, and MCP servers worth routing through ADR-007.
5. **What stays the same:** a dependency is still a visible act, still pinned, still removable; `memory/` and the vault are still off limits to anything third-party; the cockpit still loads nothing remote at runtime. The toolbox makes the act cheap; it does not make it silent.
