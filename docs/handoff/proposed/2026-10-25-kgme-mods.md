# Handoff 0059 (proposed) — KGME mods: a cockpit pane beside the chat and `/capture`, under one rule for what a mod may hook

## Why
Claude Code mods are small TypeScript modules that run inside Claude Code's own process, hook its events (`tool.call`, `prompt.submit`, `ui.render`, `command.run`, `session.start`) and reach the world only through the engine's `$` interface: the UI, the clock, HTTP, files, processes, the model, the session's credentials. No Node, no DOM, no `eval`, and no permission prompt either: a mod has what Claude Code has. `claude plugin validate <folder>` reads a mod the way the engine will and lists every event it hooks and every `$` call it makes.

Michou, 2026-10-25, on the reel's three examples: the terminal UI is the gain, per-prompt model routing is not (KGME decides the model at the session, by handoff, level and fence; a mod inside one session is blind to all three), and inter-session passing is for HANDOFF-0048 later. Two of KGME's own ideas are mods almost verbatim: a pane over `/api/events` beside the chat, and a `/capture` command so his words reach the vault without leaving the prompt (HANDOFF-0050's rule, "capture on his word"). A mod that hooks tool calls or runs processes is policy, and policy is a human path; this handoff sets that rule before the first mod exists.

## What
1. **ADR-024 — mods** (draft for Michou's acceptance, `status: proposed`). Four lines. KGME's own mods live under `mods/<name>/` in the repository, one folder each, loaded with `--plugin-dir` by `kgme session` from `kgme.toml [mods]`, which names the mods each level loads; `loose` and `cheap` load none (an unattended session draws no UI and gets no process surface it did not have). A mod hooks `tool.call`, `prompt.compose` or `prompt.submit`, or calls `$.process`, `$.fs` outside the repository, `$.model` or `$.http` beyond loopback, only when the handoff that brings it in names the hook or call and why; the committed policy (hooks, deny list, guard) stays the boundary and no mod replaces it. A third-party mod enters through a toolbox row (ADR-020) with its sha and the `claude plugin validate` listing recorded in the row's handoff. `make check` runs `claude plugin validate` on every folder under `mods/`, and a listing that names a hook or call the folder's handoff did not is `blocking`.
2. **`mods/kgme-cockpit/`: the pane.** `session.start` opens a pane; a `ui.render` hook draws it from `$.state`; `$.clock.every(2000)` polls `http://127.0.0.1:8642/api/events?since=<cursor>` with `$.http.fetch` (loopback only) and updates the state. It draws what the server returns: the runs and their states, the last events, the strip for a waiting intent, the flood for a blocked run, "server not reached" when the fetch fails, the last snapshot kept. It decides no state itself (0037's rule) and binds no keys the page binds. A status-line entry shows the newest run's state. Surfaces: terminal and desktop; the elements come from `$.ui.resolve(e)`.
3. **`mods/kgme-capture/`: `/capture`.** `$.command.register({ name: "capture" })` in `session.start`; a `command.run` hook takes `<kind> <words>` and runs `$.process.run(["kgme", "capture", kind, words])` from the repository root, returning what `kgme capture` printed, verbatim. The one `$.process` call in this handoff, named here: it runs KGME's own command with Michou's words and nothing else; its tool call goes through the hooks and the ledger like any other.
4. **The launcher.** `kgme session` passes `--plugin-dir mods/<name>` for each mod `[mods]` names for the level; the template files under `control/policy/sessions/` are unchanged. The `kgme.toml` diff: `[mods] work = ["kgme-cockpit", "kgme-capture"]`, `tight = ["kgme-cockpit"]`, `loose = []`, `cheap = []`.
5. **Not in this handoff:** any mod that routes prompts between models; any `tool.call` hook; inter-session passing (HANDOFF-0048, when crew exists); installing anyone else's mod.

## Outputs

## Acceptance test (under ten minutes)
`claude plugin validate mods/kgme-cockpit` lists `session.start`, `ui.render`, `$.ui`, `$.clock`, `$.http`, `$.state` and nothing else; for `mods/kgme-capture`, `session.start`, `command.run`, `$.command`, `$.process` and nothing else; both pass `claude plugin test`. In a `work` session with `kgme cockpit` running, the pane shows the session's own run turning waiting and back within two seconds of a tool call; with the server stopped it says so and keeps the last snapshot. `/capture friction "the pane is too wide"` prints what `kgme capture` printed and the line is in the vault verbatim. A `loose` session's command line carries no `--plugin-dir`. Planting a `tool.call` hook in a mod folder turns `make check` red.
