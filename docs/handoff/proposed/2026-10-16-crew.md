# Handoff 0048 (proposed) — `kgme crew`: KGME-owned worktrees, any model as builder, the plan and every task iterated until they pass, one merge gate, Michou's approval at the end

## Why
Michou, 2026-10-16: "There should be a mode that plans and executes and can disperse multiple agents in worktrees to build dynamic features. the thing it omits will be the final approval phase which should go through me." Then: "in the crew level the plan is iterated upon until it passes WITHOUT my intervention", and "KGME should have a streamlined worktree creation, quarantine, secruity scanning, and merging process so that agents can work freely and merges can be automatically sanity checked. this should happen seamlessly across models ultimately ... which I assume would NOT be through claude's dedicated agentic worktrees." ADR-022 §2 and §8 fix the contract; this builds it on the engine of HANDOFF-0043.

## What
1. **Workspaces.** `kgme workspace create|list|quarantine|release|remove`. A task's worktree lives under `kgme.toml [crew] root` (proposed `~/Projects/kgme-work/`), outside the repository and outside every harness's own folder, on `crew/HANDOFF-NNNN/<task>` from the integration branch's head, with `task.json` (`Outputs`, acceptance check, harness, model, level). The guard treats the worktree's top level as the repository for path checks; the ledger stays the main checkout's (HANDOFF-0047 §3). `quarantine` kills the task's process group, renames its branch `quarantine/<run>/<task>`, moves the worktree under `<root>/quarantine/`, removes write permission, and appends a `blocking` outcome; `release` and `remove` are Michou's commands and refuse to run from a session at any level.
2. **Adapters.** `kgme/adapters/claude.py` (`claude -p --agent kgme-builder` through `kgme session loose`, stream JSON, hooks ledgered as today) and `kgme/adapters/codex.py` (`codex exec --json` under the `codex-builder` profile of HANDOFF-0042 with the worktree as its only writable root; its JSON events become ledger intents and outcomes, as the canary stream parser already does). One interface: `start(task)`, `events()`, `kill()`. An adapter builds at `loose` only after its conformance cells pass: every tool call in the main ledger with the task id; a write outside `Outputs` stopped in flight where the harness can, and always at the gate; a stalled run killed with its children and quarantined; the branch based on the integration head. A local-model adapter follows router v0 on the same cells.
3. **The plan iterates until it passes.** `kgme crew --handoff HANDOFF-NNNN` starts the planner (the `kgme-planner` skill at `work`). It writes `logs/scratch/crew/<run>/plan.md`: tasks with `Outputs`, acceptance check, harness and model (default from `kgme.toml [crew]`), and blocking edges. The plan gate (`kgme crew check-plan`, mechanical) refuses a plan in which a task lacks `Outputs` or an acceptance check, two tasks' `Outputs` overlap without an edge between them, the graph has a cycle, an `Outputs` path is human or blocklisted, or the parallel width exceeds the cap; a red plan gate goes back to the planner and is not reviewed. A green plan goes to a reviewer of a different vendor than the planner; findings go back to the planner with the previous table, the planner revises and writes dispositions, disputes go to the arbiter, and the cycle repeats until PASS. Nothing is put to Michou. A persistent blocking finding on the plan goes to the arbiter board (ADR-023) and the planner executes the ruling. The plan stops only when progress stops (a recommended option executed twice with the same finding returning, a plan already seen, the budget) or a ruling falls outside the mandate; a stopped plan dispatches nothing and sends the packet.
4. **Dispatch and build.** Up to `[crew] parallel` tasks (default 3) whose edges are satisfied start, each in its workspace through its adapter, each through the 0043 loop: gate, review by a different vendor than its builder, dispositions, rulings by the arbiter board executed by the builder (ADR-023), stops only on measured non-convergence or a ruling outside the mandate, the dead-man switch. A halted task is quarantined; its dependents wait; independent tasks continue. The provider window at 90 % pauses the crew and resumes it.
5. **The merge gate, identical for every model.** Before a task branch merges into `crew/HANDOFF-NNNN`: changed paths a subset of its `Outputs`; no human path, blocklisted path, symlink or binary; a pinned secret scanner (gitleaks proposed, a toolbox row under HANDOFF-0044, run offline on the diff) finds nothing; no zero-width or bidirectional control character in any changed text; a dependency change carries its toolbox row; `make check` and the task's acceptance check pass on the merge result. A mechanical failure quarantines the task; a review finding goes back to its builder. The integrator (`kgme-integrator` skill) merges in plan order; a conflict is a `blocking` outcome on the later task, rebuilt on the new head.
6. **Integration and approval.** On the integration branch: the full gate, the handoff's acceptance suite, one integration review by a different vendor than the majority of builders. Then `outcome` `awaiting approval` naming the commit, and one screen: plan cycles, tasks by harness and model, cycles and strikes, quarantines, audits, the gate, the diff by path. `kgme approve --handoff HANDOFF-NNNN --sha <sha>`, typed by Michou, appends the `approval` event and fast-forwards `main`. The crew pushes only `crew/*` branches; nothing else merges.
7. **Roles as skills, agents thin.** `skills/kgme-planner/SKILL.md`, `skills/kgme-builder/SKILL.md`, `skills/kgme-integrator/SKILL.md` carry the role; `.claude/agents/kgme-*.md` and the Codex prompts only load them (`model: inherit`; the adapter passes the model from `kgme.toml`). `kgme skills install` (Michou's command) links each skill into `~/.claude/skills/` (the global directory Michou named, 2026-10-16) and `~/.agents/skills/` (Codex's user skills; Codex follows symlinks), and into the repository's `.claude/skills/` and `.agents/skills/`; a harness that will not follow a link gets a copy whose hash `kgme lint` checks against the repository. It refuses to overwrite a skill of the same name it did not install, and never touches `~/.claude/skills/synced/` (Claude's own skill sync). As of 2026-10-16 that directory holds `grill-me` and `synced/` only, and Michou's shortcut `~/Skills` points to it. Cowork drafts the skills and agent files as proposals under `docs/handoff/proposed/agents/`; Michou applies them; they are human paths.

Dispatch builds one task with Claude Code reviewed by Codex and one with Codex reviewed by Claude, each in a KGME workspace outside the repository; all tool calls of both land in the main ledger. The rest integrate, the crew stops at `awaiting approval`, and `kgme approve` fast-forwards `main`.
